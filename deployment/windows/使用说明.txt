MyHome Windows 一键部署包（产物直跑，Windows 10/11 x64）

本包已包含部署脚本、所需运行环境（JDK 21、MySQL 8.4、VC++）和构建好的应用产物包。
应用不再现场拉源码编译：首次部署把随包携带的产物包（后端 fat JAR + 两份已构建前端 + schema 快照）
解到安装目录的 app\，用 java -jar 起后端；后端单端口（8080）同时托管管理后台（/admin/）与 C 端（/）。
首次部署可离线，全程不编译；只有「部署最新」需要联网（从 GitHub Release 拉新产物包）。日常启停可离线。

一、电脑要求
1. Windows 10/11，Intel/AMD 64 位电脑；不支持 ARM、Windows 7 或 32 位系统。
2. 建议至少 8GB 内存、8GB 可用磁盘，照片/视频另计；使用本地 NTFS 磁盘。
3. 接通电源，部署过程中不要合盖睡眠；只有「部署最新」必须联网。
4. 使用平时登录 Windows 的账号；仅安装微软 VC++ 运行库时可能弹出管理员确认。
   不要换另一个 Windows 账号运行整个部署脚本。

二、第一次部署
1. 将 MyHome-OneClick.zip 完整复制到目标电脑并“全部解压”，进入 windows-x64 子目录。
   不要在压缩包窗口内运行，不要只复制 .cmd/.ps1，runtime\ 必须与入口脚本同级。
2. 双击 01-deploy.cmd。
3. 如弹出 VC++ 安装确认，核对发布者为 Microsoft 后允许安装。
   如果要求重启电脑，重启后再双击 01-deploy.cmd。
4. 等待本地文件校验、环境解压、产物包解到 app\、建库（空库冷启动先 load schema 快照）、后端启动完成。
   全程不联网、不编译，通常几十秒到两三分钟即完成。
5. 看到 Ready 后打开 http://localhost:8080/；关闭已完成的脚本窗口不影响后台运行。

包内内容：
  01-deploy.cmd / 02-start.cmd / 03-stop.cmd / 04-update.cmd  部署、启动、停止、部署最新入口
  myhome-windows.ps1                         一键部署核心
  packages.json                              版本、更新通道及 SHA-256 完整性清单
  runtime/                                   JDK 21、MySQL 8.4、VC++ 安装包，以及应用产物包 MyHome-app-payload.zip

脚本逐个核对包内工具链文件与产物包哈希；缺文件或损坏会停止并指出原因。产物包随包携带，
首次部署解到安装目录的 app\（含 family-home-server.jar、admin\、h5\、schema-snapshot.sql、version.json）。
数据库口令、登录令牌密钥、密码本密钥、传输盐都每次首次安装独立生成并持久化，不附带开发机密钥。

三、初始化和登录
数据库只做初始化，不导入测试业务数据：
- 保留“大宝、小宝”两个初始账号，以及文件分类、菜品分类/做法基础字典、购物车版本状态。
- 相册、图片、视频、文档、菜品、购物车条目、订单和密码本内容从空开始。
- 不运行演示造数脚本，不导入开发机数据库或媒体；重复部署不删除已有内容，不重置密码。
- 数据库迁移由后端启动时的 Flyway 从 JAR 的 classpath 自动执行（迁移随 JAR 一起发布，无独立 SQL 文件）；
  空库冷启动时引擎先 load 产物包内的 schema-snapshot.sql（内含真 Flyway 历史），绕开空库严格重放的崩溃。
  请不要手工逐个导入 SQL，不要删除 Flyway 历史或执行清库脚本。

C 端：http://localhost:8080/
管理后台：http://localhost:8080/admin/
（两端都由后端 8080 单端口托管，同源；旧的 5173/5174 已随源码直跑模型退役。）
首次空库选择大宝（管理员）或小宝，初始密码均为 123456。
请分别登录管理后台个人中心修改自己的密码；管理员不能替别人重置密码。
只允许当前电脑访问，手机、其他电脑和公网访问不包含在本包中；不要改用局域网 IP。

四、日常启停与部署最新
Windows 重启后：双击 02-start.cmd；服务已运行时此入口也可重启应用（离线可用）。
准备停止或备份：结束上传/编辑后双击 03-stop.cmd，等显示 Stopped。
部署最新版本：双击 04-update.cmd（需联网）。它从 GitHub Release 拉最新产物包、校验 SHA-256、
  原子替换 app\、再重启后端；后端重启时 Flyway 随新 JAR 自动补跑增量迁移。校验通过前绝不触碰现有 app\。
  更新期间会有几秒服务中断，后端重启完成后才恢复访问。
  管理后台「部署管理」页在运行版本落后于最新发布版本时也会出现「部署最新」入口，可实时看进度与部署历史。
不需要每天运行 01-deploy.cmd；它用于首次安装。保留整个解压目录，后续还要使用脚本。
不安装开机自启、不修改防火墙、全局执行策略或电脑睡眠设置。

五、数据与备份
默认安装位置：%LOCALAPPDATA%\MyHome
  app\                应用产物（family-home-server.jar + admin\ + h5\ + schema-snapshot.sql + version.json）
  data\mysql          私有数据库（端口 13306）
  data\files          公共图片、视频和文档
  data\files-private  私人图片、视频和文档
  state               DPAPI 保护的密钥、运行环境、版本与进程记录
  tools               私有运行环境（JDK 21 / MySQL 8.4）
  logs                操作及服务日志

数据库、整个 data 和 state 必须一起保留；不要删除 secrets.xml 或重新生成密钥。
DPAPI 绑定原 Windows 账号和原电脑，复制目录不等于支持换机/重装后的恢复。
本包未提供跨机密钥导出。重要数据请安排独立备份；同机备份也应先停止应用和数据库。
不要向正在运行的目录覆盖备份。

六、失败处理
窗口会显示失败步骤、具体原因、可用退出码/脚本行号和相关日志；等待按键后才关闭。
1. 包内工具链文件、产物包缺失或校验失败：重新完整复制、解压同一个一键部署包，不要下载同名文件混用。
2. 「部署最新」联网失败：检查网络后重试 04-update.cmd；需能访问 github.com 的 Release 下载地址。
   日常 01-deploy.cmd/02-start.cmd/03-stop.cmd 不需要联网。
3. 端口占用：后端 8080、私有 MySQL 13306（只有这两个端口）。只退出你确认的冲突程序；脚本不杀未知进程。
4. 目录不为空或检测到旧版（源码/离线）安装：不接管旧安装，不把新包覆盖到旧数据上；请先备份并规划迁移。
5. 无法解密：用原电脑、原 Windows 账号和原安装路径；不要删除 state 重试。
6. MySQL/迁移错误：保留原日志，不清库、不删 Flyway 历史、不手工导入 SQL。
7. 安全策略或防护拦截：不要关闭防护，请由管理员核对本包与具体错误。

操作记录：logs\Deploy.log、logs\Start.log、logs\Stop.log、logs\Update.log。
服务日志：logs\mysql-error.log、logs\backend.err.log、logs\server.log。
（管理后台「系统日志」页可实时查看这些 .log。）
失败发生在创建日志之前时，以窗口里的原始错误为准。
操作日志会脱敏常见密码/令牌，服务原日志和个人信息仍需人工检查；
不要发送 state、secrets.xml、mysql-client.ini、mysql-init.sql。

七、自定义安装目录
在部署包目录打开命令提示符：
  01-deploy.cmd -InstallDir "D:\MyHome"
以后必须继续使用同一目录：
  02-start.cmd -InstallDir "D:\MyHome"
  03-stop.cmd -InstallDir "D:\MyHome"
  04-update.cmd -InstallDir "D:\MyHome"
选择本地 NTFS 短路径，避免 %, &, ! 和双引号；不要使用网络盘、同步盘或 U 盘作为运行目录。

八、验证边界
应用产物随包携带（构建期由 build-payload.py 产出：后端 fat JAR + 两份已构建前端 dist + schema 快照 + 版本戳），
「部署最新」从 packages.json 指定的 GitHub 仓库 Release 拉取新产物包；state\installed.json 记录本次部署的版本与提交号。
环境来自固定官方发行归档并核对哈希；VC++ 使用包内固定微软安装文件，仍由 Windows 展示 UAC 发布者。
当前制作环境为 macOS；原生 PowerShell 5.1、UAC、DPAPI、NTFS、Windows MySQL 8.4，
以及 myhome-windows.ps1 的产物解包、单端口托管、GitHub Release 真下载与自重启，仍需 Windows 真机验收。
静态语法和隔离检查不能替代该验证。
