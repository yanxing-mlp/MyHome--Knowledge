# MyHome 执行说明（一键部署包 · 联网源码直跑 · Windows / macOS / Linux 共用）

> 本说明三个平台共用一份。命令按平台分块给出，差异集中在第 2 节的对照表。
> 你只需要看自己平台对应的那一列／那一块，其余内容（成功判据、日志、保留边界）三平台完全一致。

## 1. 当前模型与适用范围

**模型：联网 · 源码直跑。** 工具链（JDK 21、Node 22、Maven、pnpm、MySQL 8.4）随包提供并逐一核对 SHA256，**不联网下载工具链**；应用源码不随包携带，部署时按 `packages.json` 里的 GitHub 地址联网克隆，后端 `mvn spring-boot:run`、前端 `pnpm dev` 直接跑源码，不预编译 JAR 或静态产物。**首次部署和「部署最新」都需要联网；日常启动／停止可离线。**

适用平台（每个平台只认自己的架构，脚本启动即校验，不符直接退出）：

| 平台 | 子系统 | 架构 |
|---|---|---|
| `windows-x64` | Windows 10 / 11 | Intel / AMD x64（不支持 ARM） |
| `macos-arm64` | macOS（Apple Silicon） | arm64（不支持 Intel Mac） |
| `linux-x64` | Ubuntu / Debian 系 | x86_64（不支持 arm64、不支持 RHEL/dnf） |

一律使用自己的**普通账号**运行。Windows 上微软 VC++ 安装器需要时会单独弹 UAC；Linux 上**不要**用 `sudo bash ...` 跑整套部署（只在系统提示安装 git 等前置时按指引单独 sudo）。三平台都只绑定 `127.0.0.1`，不改防火墙、不改全局配置、不杀未知进程、不清库、不删密钥。

## 2. 平台差异对照表

| 维度 | Windows x64 | macOS arm64 | Linux x64 |
|---|---|---|---|
| 入口脚本 | `01-deploy.cmd` 等（双击或 PowerShell 调用） | `bash 01-deploy.sh` 等 | `bash 01-deploy.sh` 等 |
| 引擎 | `myhome-windows.ps1`（PowerShell 5.1） | `myhome-unix.sh`（bash） | `myhome-unix.sh`（bash） |
| 默认安装目录 | `%LOCALAPPDATA%\MyHome` | `~/Library/Application Support/MyHome` | `~/.local/share/MyHome` |
| 自定义安装目录 | `.\01-deploy.cmd -InstallDir "D:\MyHome"` | `bash 01-deploy.sh --install-dir "$HOME/MyHome"`（或 `MYHOME_INSTALL_DIR`） | 同 macOS |
| Git 来源 | 随包便携版（`runtime\` 内 MinGit） | **系统 git**（缺失时提示 `xcode-select --install`） | **系统 git**（缺失时提示 `sudo apt-get install -y git`） |
| 密钥保护 | DPAPI 加密 `state\secrets.xml`（绑定本机+本账号） | `state/secrets.env` 权限 0600 + `state` 目录 0700 | 同 macOS |
| 磁盘要求 | 本地 NTFS（硬链接去重需要） | 本地磁盘 | 本地磁盘 |
| 额外前置 | VC++ 运行库（随包，必要时弹窗装） | 无（命令行二进制已清除隔离属性） | 无 |
| MySQL | 私有实例 `127.0.0.1:13306`，数据在 `data\mysql` | 同左（macOS arm64 官方 tarball） | 同左（minimal tarball） |

> 端口三平台一致：数据库 `13306`、后端 `8080`、管理后台 `5173`（路径 `/admin/`）、C 端 `5174`（路径 `/`）。
> 目录结构三平台一致：`src/{server,web}`、`data/{mysql,files,files-private}`、`state`、`tools`、`logs`。

## 3. 先核对包，再运行

完整解压总包后，进入你平台对应的子目录。以下路径只是示例，请换成自己解压后的实际位置。

**Windows**（开始菜单打开 PowerShell）：

```powershell
Set-Location "D:\MyHome-Deploy\windows-x64"
Get-Location; Get-ChildItem
```

**macOS / Linux**（终端）：

```bash
cd "$HOME/MyHome-Deploy/macos-arm64"   # Linux 换成 linux-x64
pwd; ls -l
```

当前位置必须能直接看到（`runtime` 必须与入口脚本同级，不能挪到总包顶层，也不能换成别的平台文件）：

```text
01-deploy.*   02-start.*   03-stop.*   04-update.*
myhome-windows.ps1 或 myhome-unix.sh
packages.json
runtime/
```

不要在压缩包预览窗口里直接运行，不要只复制脚本而漏掉 `runtime/`。

## 4. 第一次部署

先确定**应用安装目录**。它与「解压包目录」是两个不同位置：解压包目录放脚本和工具链，安装目录放源码、数据库、上传文件和密钥。以后启动、停止、部署最新必须始终使用**同一安装目录、同一账号**。

**Windows**（安装目录示例 `%LOCALAPPDATA%\MyHome`，也可改成 `D:\MyHome` 这种本地 NTFS 短路径，避免 `%`、`&`、`!`、双引号和网络盘）：

```powershell
$InstallDir = Join-Path $env:LOCALAPPDATA 'MyHome'
.\01-deploy.cmd -InstallDir "$InstallDir"
$LASTEXITCODE      # 必须是 0
```

**macOS / Linux**（不传 `--install-dir` 时用第 2 节的平台默认目录）：

```bash
bash 01-deploy.sh --install-dir "$HOME/MyHome"
echo "退出码：$?"   # 必须是 0
```

脚本会：校验工具链哈希 → 解压安装到 `tools/` → 联网克隆源码到 `src/server`、`src/web` → 下载 Maven / npm 依赖 → 初始化私有 MySQL → 启动后端（Flyway 自动从源码建库迁移）→ 启动两个前端 dev server → 健康检查。

- Windows 上若 VC++ 安装要求重启，先重启，再用同一账号、同一安装目录重跑这条命令。
- 首次运行要现下依赖并编译，后端健康检查最长等待约 15 分钟，属正常现象。
- 数据库迁移由后端启动时的 Flyway 从 `src/server` 源码自动执行。**不要自己逐个导入 SQL，不要删除迁移历史，不要执行清库脚本。**
- macOS 首次运行命令行二进制时，引擎已自动清除下载隔离属性；若系统仍拦截，到「系统设置 → 隐私与安全性」放行一次即可。

## 5. 如何确认部署成功

以下三项都通过才算成功；只看见某个端口有进程并不够。

### 5.1 脚本结果

窗口出现 `Ready. Open these addresses ON THIS ...:` 且退出码为 `0`（Windows 看 `$LASTEXITCODE`，macOS/Linux 看 `echo $?`）。出现非零、`FAILED` 或失败原因时，不要当作成功。

### 5.2 后端与数据库健康检查

**Windows**（PowerShell，任意目录）：

```powershell
$r = Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/b/health' -TimeoutSec 10
$r | ConvertTo-Json -Depth 4
if ([string]$r.code -ne '0' -or $r.success -ne $true -or $r.data.app -ne 'family-home-server' -or [string]$r.data.db -notlike 'MySQL *') {
    throw '后端或数据库健康检查未通过，请查看部署和服务日志。'
}
```

**macOS / Linux**（终端，任意目录）：

```bash
curl -fsS http://127.0.0.1:8080/api/b/health
echo
# 期望 JSON 含 "code":"0"、"success":true、"app":"family-home-server"、"db":"MySQL ..."
```

连接失败、超时、HTTP 错误或字段不符都不算通过。

### 5.3 浏览器检查

在**同一台机器**打开：

- C 端：<http://localhost:5174/>
- 管理后台：<http://localhost:5173/admin/>

两端都应显示正常登录页，而不是空白页或资源加载错误。全新数据库选择「大宝」或「小宝」，密码均为 `123456`；登录后能进首页，刷新仍能打开。随后分别到管理后台个人中心修改各自密码。已部署过的库请用你自己改过的密码，本脚本**从不重置已有账号密码**。

新库只保留两个账号、基础字典和系统状态，不应出现测试菜品、订单、图片、视频、文档或密码本内容；检查时不需要新建测试业务数据。这里只支持本机访问，手机或局域网 IP 打不开不代表失败，不要为此关防火墙或改认证。

## 6. 日常启动 / 重启（离线可用）

回到脚本目录，使用与首次部署**完全相同**的安装目录。

**Windows**：

```powershell
Set-Location "D:\MyHome-Deploy\windows-x64"
$InstallDir = Join-Path $env:LOCALAPPDATA 'MyHome'
.\02-start.cmd -InstallDir "$InstallDir"
$LASTEXITCODE
```

**macOS / Linux**：

```bash
cd "$HOME/MyHome-Deploy/macos-arm64"   # 或 linux-x64
bash 02-start.sh --install-dir "$HOME/MyHome"
echo "退出码：$?"
```

返回码 `0`、显示 `Ready` 后，再做第 5 节的健康和浏览器检查。`02-start` 复用已克隆的源码，不联网拉取；要更新到最新代码用第 7 节。

## 7. 部署最新代码（需联网）

**Windows**：

```powershell
$InstallDir = Join-Path $env:LOCALAPPDATA 'MyHome'
.\04-update.cmd -InstallDir "$InstallDir"
$LASTEXITCODE
```

**macOS / Linux**：

```bash
bash 04-update.sh --install-dir "$HOME/MyHome"
echo "退出码：$?"
```

它对 `src/server`、`src/web` 两仓执行 `git fetch + reset` 到远端 `master` 最新，随后重启前后端；后端重启时 Flyway 自动应用新增迁移。更新期间会有几秒服务中断，前后端都重启完成后才恢复。返回码 `0` 且显示 `Ready` 后，再做第 5 节检查。本次部署的提交号记录在 `state/installed.json`。

> 管理后台「部署管理」页在运行版本落后于最新提交时会出现「部署最新」入口，点击后由后端分离拉起 `deploy-now.*` 执行同一套 update 流程，并在页面上实时显示进度。

## 8. 停止服务

先结束上传、播放和未保存编辑，再在脚本目录执行（安装目录保持一致）：

**Windows**：

```powershell
$InstallDir = Join-Path $env:LOCALAPPDATA 'MyHome'
.\03-stop.cmd -InstallDir "$InstallDir"
$LASTEXITCODE
```

**macOS / Linux**：

```bash
bash 03-stop.sh --install-dir "$HOME/MyHome"
echo "退出码：$?"
```

看到 `Stopped. Data, photos and encryption keys are retained.` 且返回码 `0` 才算正常结束。此入口停止本安装的前后端和私有 MySQL，保留数据及密钥。

可补充查看监听情况，本安装停止后不应再由它监听这四个端口；若还有输出，先核对进程归属，**不能仅凭端口号结束其他程序**。浏览器可能仍显示缓存页面，不要据此判断服务还在运行。

**Windows**：

```powershell
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in @(5173,5174,8080,13306) } |
    Select-Object LocalAddress,LocalPort,OwningProcess
```

**macOS / Linux**：

```bash
lsof -nP -iTCP -sTCP:LISTEN 2>/dev/null | grep -E ':(5173|5174|8080|13306)\b' || echo "四个端口均已释放"
```

## 9. 失败时在哪里看原因

先保留窗口中的失败步骤、具体原因、退出码和日志路径。日志目录在安装目录下的 `logs/`（Windows `%LOCALAPPDATA%\MyHome\logs`，macOS `~/Library/Application Support/MyHome/logs`，Linux `~/.local/share/MyHome/logs`；自定义安装时改成对应目录）。

第一次部署看 `Deploy.log`，启动看 `Start.log`，停止看 `Stop.log`，部署最新看 `Update.log`。服务相关日志：

| 问题 | 重点日志 |
|---|---|
| MySQL 启动失败 | `mysql-error.log`、`mysql.err.log`、`mysql-init.out.log` |
| 后端启动、依赖下载、数据库迁移或健康检查失败 | `server.log`、`backend.err.log`、`backend.out.log` |
| 前端依赖安装或 dev server 失败 | `web-admin.err.log`、`web-h5.err.log` |
| 联网拉源码失败 | `Deploy.log`、`Update.log` 里的 git 输出 |

查看最近输出（Windows 用 `Get-Content "$InstallDir\logs\Deploy.log" -Tail 80`；macOS/Linux 用 `tail -n 80 "$HOME/MyHome/logs/Deploy.log"`）。日志文件可能因尚未执行到该步骤而不存在；创建日志之前的失败以窗口原始错误为准。

常见处置：缺工具链文件或哈希不符 → 重新完整复制同版本包；联网失败 → 确认 GitHub / Maven Central / npm registry 可达后重试；macOS/Linux 提示缺 git → 按窗口指引安装系统 git 后重跑；端口冲突 → 只处理已确认属于自己的冲突程序；旧版本、已有不明目录或密钥无法解密 → 先保留原数据，不要强行覆盖。

**不要删除 `data`、`state`、密钥文件（Windows `secrets.xml` / macOS·Linux `secrets.env`），不要清空 MySQL 或重置 root 认证，也不要关闭系统防护来重试。** 分享日志前检查隐私，不发送密钥、配置凭据或数据库初始化口令文件（`mysql-client.*`、`mysql-init.sql`）。

## 10. 必须保留的内容与验证边界

运行目录下的 `src`、`data/mysql`、`data/files`、`data/files-private` 和整个 `state` 都要保留。备份前先正常停止应用及数据库。

- **Windows**：DPAPI 密钥绑定原电脑和原 Windows 账号，复制目录不等于支持换机恢复。
- **macOS / Linux**：密钥是 `state/secrets.env`（0600）。换机恢复必须连同 `data/` 与 `state/` 一起迁移，并用同一账号；只拷 `data/` 不拷 `state/` 会导致密码本等加密数据无法解密。

**验证边界（如实告知）**：

- macOS arm64 引擎已在真机完成功能性验证：工具链解压与探针（JDK/Node/Maven/pnpm/MySQL 实际可执行）、幂等重装、密钥生成与传输盐校验、`runtime.env` 往返、私有 MySQL 完整生命周期（initialize-insecure → init-file 建库建用户 → SQL 查询 → 安全关闭 → 端口释放 → 重启数据仍在）。
- 尚未在真机跑完整链路的部分：macOS 的 `git clone + mvn spring-boot:run + pnpm dev + 后端健康检查` 全流程、Linux x64 的全部流程、Windows 的 PowerShell 5.1 / UAC / DPAPI / NTFS 原生验收。这些目前为静态校验。
- 本说明的命令已与现有脚本入口逐条核对，不代表上述原生全链路验收已完成。
